优化阿里云的 CDN 流量

CDN 流量优化实战指南

1. 核心问题：为什么有 Etag 还有流量消耗？

很多开发者认为有了 Etag (304 Not Modified) 就万事大吉了，但实际上：

  • 协商缓存 (Etag/304): 客户端每次都要发请求问服务器“变没变”。虽然不传图片内容，但会产生HTTP 请求头流量和CDN 请求次数费用。积少成多，流量依然可观。
  • 强缓存 (Cache-Control): 客户端直接从本地磁盘/内存读取，完全不发起网络请求。流量消耗为 0。

目标： 将图片加载从“协商缓存”升级为“强缓存”。

2. 最佳实践策略：Immutable 模式

采用 “文件名/URL 变更即更新，内容不变则永久缓存” 的策略。

  • 配置目标： 让客户端缓存图片 1 年 (31536000秒)。
  • 更新机制： 如果图片内容需要修改，不要在原文件名上覆盖，而是修改文件名（如 banner-v1.jpg -> banner-v2.jpg）或 URL 参数。

3. 阿里云 CDN 配置步骤

入口： 阿里云 CDN 控制台 -> 域名管理 -> [目标域名] -> 缓存配置。

3.1. 步骤一：配置客户端强缓存 (关键)

这是让小程序/浏览器不发请求的核心。

  1. 切换到 【修改出站响应头】 (HTTP Response Header) 标签页。
  2. 点击 添加。
  3. 配置如下：
    • 参数: Cache-Control
    • 取值: max-age=31536000, immutable
    • 策略: 拒绝 (或覆盖)
  4. 作用： 强制给所有响应加上缓存 1 年且不可变的指令。

关于 immutable: 这是一个高级指令，告诉客户端“这文件在过期前绝对不会变”，能进一步减少用户手动刷新页面时产生的 304 请求（iOS/Webkit 内核支持极佳）。

3.2. 步骤二：配置节点缓存 (省回源流量)

这是让 CDN 节点自己存住图片，少去 OSS 取货。

  1. 切换到 【缓存过期时间】 标签页。
  2. 添加规则：
    • 类型: 文件后缀
    • 内容: jpg,jpeg,png,webp,gif
    • 过期时间: 1 年
    • 权重: 99

3.3. 避坑设置

  • 客户端跟随 CDN 缓存策略： 建议 【关闭】。
    • 原因： 自动跟随往往很机械，无法添加 immutable 等高级指令。建议通过“修改出站响应头”来显式控制，逻辑更清晰。

4. 验证方法 (Chrome Network)

不要直接按 F5 刷新验证！浏览器对 F5 有特殊处理。

正确验证步骤：

  1. 打开开发者工具 -> Network。
  2. 取消勾选 Disable cache。
  3. 在地址栏输入图片 URL，按回车 (或在页面中点击链接跳转)。
  4. 观察结果：
    • Status: 200 OK (from disk cache) 或 (from memory cache)。
    • Time: 0ms 或 1ms。
    • Response Headers: 点击请求查看，必须包含 Cache-Control: max-age=31536000, immutable。

常见误区排查：

  • 现象： 状态是 200 (disk cache)，但 Header 里没有 Cache-Control。
  • 原因： 浏览器读取的是配置生效前下载的旧缓存。
  • 解决： 勾选 Disable cache 刷新一次（强行更新缓存），然后再取消勾选验证。

5. 补充：防盗链

为了防止流量被盗用，建议配置 Referer 白名单。

  • 微信小程序 Referer 格式： https://servicewechat.com/{appid}/{version}/page-frame.html
  • CDN 白名单推荐配置：
    1. servicewechat.com
    2. *.servicewechat.com
  • 注意： 开发工具中有时 Referer 包含 devtools，上述通配符已包含此情况。

6. 常见 FAQ

Q: 为什么我配置了 max-age，刷新页面还是 304？ A: 浏览器的 F5/刷新按钮 会强制加上 Cache-Control: max-age=0，迫使浏览器向服务器发起协商验证。这是浏览器标准行为。正常用户点击进入页面时，是会走强缓存的。

Q: 监控里有少量的 4xx 错误正常吗？ A: 正常。通常是 404 (图片不存在) 或 403 (防盗链拦截)。只要业务显示正常，且 4xx 比例极低，属于互联网背景噪音，可忽略。

Q: 图片刚上传，第一个访问的用户会回源吗？ A: 会。第一个用户触发 CDN 回源拉取并缓存，后续用户（以及该用户后续的访问）将直接命中 CDN 或本地缓存。如果需要极致体验，可以使用 CDN 的 “预热” 功能。
